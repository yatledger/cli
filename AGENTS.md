# AGENTS.md

Руководство для AI-агентов и разработчиков, работающих в репозитории `yat/cli`.

## Что это за проект

`yat/cli` — клиентская часть (web/PWA-кошелёк) платформы **Ять (Yat)** — децентрализованной
системы обмена ценностями на базе DAG и криптографии Ed25519. Это не ядро сети, а интерфейс:
генерация ключей в браузере, подпись транзакций, шифрование сообщений, отправка транзакций через
REST и чтение данных через GraphQL. Ядро сети (DAG, Raft и т.д.) живёт в других репозиториях.

Стадия: **ранний прототип / pre-alpha**. Часть страниц — заглушки, API тестнета может быть
недоступен.

## Стек

- **Vue 3 + Quasar 2** (`@quasar/app-vite`), Vite, Pinia, vue-router, vue-i18n.
- **Данные:** Apollo Client / `@vue/apollo-composable` (GraphQL), `ky` (REST), `idb` (IndexedDB).
- **Крипто:** `libsodium-wrappers`, `tweetnacl`, `bip39` / `@scure/bip39`, `@scure/base` (base58),
  `@noble/hashes` (pbkdf2, sha512).
- **Язык:** только JavaScript (`.js`, `.vue`). **TypeScript не используем** — пока не поступит
  отдельное указание.
- **Линт/формат:** ESLint (flat config `eslint.config.js`) + Prettier.

### Важные технические ограничения

- `libsodium-wrappers` **зафиксирован на `0.7.15`**. Версия `0.7.16` содержит сломанный ESM-билд
  (импортирует отсутствующий `./libsodium.mjs`) и ломает сборку. Не обновлять без проверки.
- В используемой сборке libsodium **нет `crypto_pwhash`**, поэтому KDF реализован на
  `@noble/hashes` (pbkdf2 + sha512). Не полагаться на `crypto_pwhash`.
- Алиасы путей: `src/...`, `boot/...`, `stores/...`, `components/...`, `pages/...`,
  `layouts/...`. **`services/` алиасом не является** — импортировать как `src/services/...`.

## Модель безопасности кошелька (не ломать)

- Мнемоника — 24 слова (BIP39), ключи Ed25519 выводятся из seed (`crypto_sign_seed_keypair`).
- Сид-фраза шифруется и хранится **только в IndexedDB** (БД `yat`, store `settings`, ключ `seed`)
  в версионированном формате `{ v, salt, nonce, ciphertext }` (см. `src/services/wallet.js`).
- **Никогда** не сохранять мнемонику/приватные ключи в cookie, localStorage или на сервер.
- После перезагрузки ключи в памяти отсутствуют — нужен повторный вход по паролю.
- Вся криптография сида — в `src/services/wallet.js`; не размазывать по страницам.

## Структура

```
src/
  boot/         crypt.js (сообщения), env.js (валидация env), apollo.js, i18n.js, db.js
  services/     wallet.js (шифрование/хранение сида)
  stores/       user.js (Pinia: sk, pk, seed, mk, crypt, ready)
  components/   SignIn.vue, SlideShow.vue
  pages/        страницы и подпапки user/, landing/
  layouts/      MainLayout.vue
  router/       routes.js
  i18n/         en.js, ru.js
e2e/            Playwright-тесты
scripts/        serve-dist.mjs (SPA-сервер для e2e)
```

## Команды

```bash
npm install              # установка зависимостей
cp .env.example .env     # настроить GQL_API и REST_API
npm run dev              # dev-сервер (http://localhost:9000)
npm run build            # production-сборка в dist/spa
npm run lint             # ESLint
npm run format           # Prettier
npm run test:e2e         # сборка + Playwright (системный Chrome)
```

Обязательные переменные окружения: `GQL_API` (GraphQL), `REST_API` (REST, с завершающим `/`).
Их валидирует `src/boot/env.js`. Секреты и `.env` в репозиторий не коммитить.

## Скилл `coder`

Для внесения правок и добавления функционала используй скилл
`.agents/skills/coder/SKILL.md`. В нём собраны незыблемые правила, алиасы путей, ограничения
криптографии, подводные камни Vite/Quasar/libsodium и рабочий процесс с проверкой через
`npm run lint` и `npm run test:e2e`.

**Скилл нужно пополнять.** Если в ходе работы ты узнал новую тонкость проекта — особенность
библиотеки, подводный камень сборки, неочевидное поведение Quasar/Vite/IndexedDB или удачный
рецепт — **добавь это знание в соответствующий раздел `SKILL.md`**, чтобы следующая правка была
быстрее и безопаснее. То же касается `AGENTS.md`: держи оба документа в актуальном состоянии.

## Правила работы

1. **Не вносить фундаментальных изменений, меняющих логику.** Правки должны быть минимальными и
   в рамках поставленной задачи, без лишних изменений «заодно».
2. **При крупных правках спрашивать разрешение** у пользователя до начала работы.
3. **Никакого TypeScript** — только JavaScript, пока не поступит отдельное указание.
4. **Не писать unit-тесты.**
5. **Не писать комментарии в коде.**
6. **При добавлении функционала покрывать его e2e-тестами и сохранять их** в `e2e/`.
   Запускать `npm run test:e2e` и убеждаться, что проходит.
7. Соблюдать существующий стиль: отступы 2 пробела, без точек с запятой (см. `.editorconfig`
   и ESLint `semi: ['error', 'never']`), локализация через `$t` для обеих локалей (en/ru).
8. Перед завершением задачи прогонять `npm run lint` (0 ошибок).

## E2E-тестирование

- Playwright (`@playwright/test`), конфиг `playwright.config.js`.
- Используется **системный Chrome** (`/usr/bin/google-chrome-stable`), без скачивания браузера.
  Путь переопределяется через `CHROME_PATH`.
- Сборка отдаётся через `scripts/serve-dist.mjs` (history-fallback), порт 9100.
- Тесты лежат в `e2e/*.spec.js`; текущий набор — `e2e/wallet.spec.js`.
- Пользовательские сценарии проверяются через реальный UI в браузере (клики, формы, IndexedDB).
- Артефакты (`test-results`, `playwright-report`) в `.gitignore`.

## Чего избегать

- Хранить секреты (сид, приватные ключи, `.env`, TLS-ключи) в git.
- Смешивать криптографию сида по страницам вместо `src/services/wallet.js`.
- Обновлять `libsodium-wrappers` без проверки сборки и e2e.
- Добавлять новые «удобные» алиасы/зависимости без согласования.
